## What this is

A **shared photo-album service** (built from a Claude Design handoff). People create an album, share an unguessable link, and everyone's photos/videos land in one timeline. There is **no public feed, no directory, no "my albums" dashboard** — the album's `slug` is the only way in.

The **model layer** and these screens are built (Phlex views — see *View layer*): the **landing page** (`Albums#index`, the site **root** — "Create an album" CTA, admin-only), the album timeline (`Albums#show` — day-grouped grid + a participant **people-filter** popover), the single-moment detail (`Moments#show` — photo or `<video>` player + comments sidebar), and a custom not-found page. Open the seeded album in dev at **`/albums/test`** (fixed slug).

## Stack

Rails 8.1 · Ruby 4.0 · **SQLite** · Hotwire (Turbo 8 + Stimulus) · Solid Queue/Cache/Cable · Active Storage · **Vite** (`vite_rails`) for JS/CSS bundling. View layer is **Phlex** (`phlex-rails` + `literal`).

**Config / env:** read runtime settings through the **`Config`** constant (`Config = Shimmer::Config.instance` in `config/application.rb`) — `Config.foo` resolves from `ENV["FOO"]` first, then the flat **encrypted-credential** key `foo`; `Config.foo!` raises if missing, `Config.foo?` coerces a bool. Don't read `ENV`/`Rails.application.credentials` directly. **Production secrets live in `config/credentials.yml.enc`** (committed), unlocked by **`RAILS_MASTER_KEY`** — which Kamal injects from the local `config/master.key` (gitignored). It holds `secret_key_base` (Rails resolves this automatically in prod) plus the flat `smtp_*` keys (read via `Config.smtp_*` in `config/environments/production.rb`). `HOST` is *not* a secret — it stays a plain env var (dev/test default to localhost). `.env*` files are loaded in dev/test by **`dotenv-rails`**; commit non-secret dev defaults to `.env.development` (`*.local` and `config/*.key` are gitignored; `credentials.yml.enc` is committed). See `.env.example` for the dev/non-secret vars and *Deployment* (README) for the Kamal flow.

## Conventions (n.U.T.S — nerdgeschoss handbook)

- **Fat models, slim controllers. Business logic lives in models — not service objects.** There is no `app/services`.
- **Concerns over service objects**, namespaced under their model: e.g. `User::Authentication` (`app/models/user/authentication.rb`).
- **Schema reflects the domain, not the UI.** Normalize; don't carry UI-shaped denormalized data.
- Stick to Rails defaults. POROs are valid models when no persistence is needed.

## Architecture decisions (non-obvious)

- **UUID v7 primary keys on every table**, including Active Storage. SQLite has no native uuid, so they're generated app-side: `ApplicationRecord` has `before_create { self.id ||= SecureRandom.uuid_v7 }`, AS records get the same via `config/initializers/active_storage_uuid.rb`, and `config.generators` uses `primary_key_type: :string`. Migrations use `id: :string` and `type: :string` on references.
- **Passwordless auth.** `User` has no password; the flow lives in the **`Login` PORO** (`app/models/login.rb`, built over the request's `cookies` jar — `Login.new(cookies)`). **`Login` is the session** — it owns the logged-in `:user_id` cookie (resolving the current user, `sign_in`, `sign_out`) and **composes two strategy POROs** for *becoming* logged in: **`Login::EmailCode`** (`app/models/login/email_code.rb`, `login.email_code`) and **`Login::Passkey`** (`app/models/login/passkey.rb`, `login.passkey`, see *Passkeys*). Each strategy is `.new(login)`, reads/writes its own cookie via `login.cookies`, verifies a user, and hands them to the shared **`Login#sign_in`** (the single place the `:user_id` cookie is set, memoizing so the rest of the request sees the user). `Login::EmailCode` owns: email-only identity (private `find_or_create_user`, race-safe), code minting (`generate_code`, honoring the `Config.login_code` / `LOGIN_CODE` override — `999999` in `.env.development`, random elsewhere), emailing (`UserMailer`), constant-time `code_matches?`, the `:pending_login` cookie. Login is a one-time code emailed and held in a cookie — never persisted (no token/session table). The pending cookie (`:pending_login`, holds `{email, code}` — email, *not* a user id, so `pending_email` needs no lookup) and the logged-in cookie (`:user_id`) are both `cookies.encrypted` with an `expires:` (`EmailCode::CODE_TTL` / `Login::LOGIN_TTL`) — cookie expiry *is* the code's TTL, so there's no manual freshness check. `SessionsController` is a thin delegator (`login.email_code.start`/`login.email_code.verify`/`login.sign_out`) that only orchestrates + does the shimmer `ui.navigate_to(request.referer)` morph; `ApplicationController#authenticate` sets `Current.user = login.user` (`login` is a memoized `Login.new(cookies)` helper there). `current_user` (a `protected` method, so subclasses can call it) delegates to `Current.user`. We don't use the Rails `session`. The passkey success paths morph back via `ui.navigate_to(safe_referer)` — `ApplicationController#safe_referer` returns the referer only if same-origin, else root (no open redirect). `SessionsController` rate-limits `create` (5/3 min **per IP and per email**, to curb email-bombing one address from many IPs) and `verify` (10/3 min per IP) via Rails' `rate_limit` (backed by the cache store; the test env's `:null_store` makes it a no-op, so it never interferes with specs).
- **`require_login`** is a shared **protected** `ApplicationController` method (`head :unauthorized unless current_user`); any controller that needs a signed-in user opts in with `before_action :require_login` (`LikesController`, `UploadsController`, `CommentsController`, `MomentsController#destroy`).
- **Admin.** Site-wide capability lives on `User` as a single **`admin` boolean column** (`User#admin?`). There are **no album-scoped roles** — anyone with the link can view, and uploading/commenting/liking simply creates the row with `current_user` as the `uploader`/`author`/`user`. Seeds: Marco is the site admin (`users.create(:marco, ..., admin: true)`); everyone else is a plain user.
- **Authorization is Pundit** (`app/policies/`). `ApplicationController` `include Pundit::Authorization` and `rescue_from Pundit::NotAuthorizedError` → `head :forbidden`. `pundit_user` is `current_user` (may be **nil** — policies must tolerate it and return false). `AlbumPolicy#create?` = **admin only**; `AlbumPolicy#update?` = **admin only**; `MomentPolicy#destroy?` = **uploader or admin**. (`ApplicationPolicy` defaults `new?`→`create?` and `edit?`→`update?`, so those follow automatically.) `Moment` is STI, so `Moment#policy_class` returns `MomentPolicy` (otherwise Pundit looks for `Photo`/`VideoPolicy`). **Components carry Pundit + `current_user`** (`Components::Base` `include Pundit::Authorization` and defines `current_user` = `Current.user`), so a component calls `policy(record).action?` / `current_user` **directly** — no `can_*`/`current_user` prop drilling from the controller. Controllers still `authorize` server-side (the policy is the real gate; the component visibility is just UI).
- **Uploads (direct upload).** The **Add photos** button (`Components::Hero#add_button`) gates on login exactly like the like button — logged out it opens the login modal (`new_session_path`), logged in it opens the **upload sidebar** (`new_album_upload_path`) as a Shimmer modal with `size: "sidebar"` (a right-docked drawer styled by `.modal--sidebar` in `modal.scss`). The sidebar (`Components::UploadSidebar`, rendered by `Views::Albums::Upload` with `layout: false`) drives **Active Storage direct upload** via `upload_controller.js` (`@rails/activestorage` `DirectUpload`): each chosen/dropped file uploads straight to storage (browser → `rails_direct_uploads_path`, CSRF token from the layout's `csrf_meta_tags`), shows a per-file progress bar, and exposes a **Retry** on failure. Uploads run through a **concurrency pool (`MAX_CONCURRENT = 5`)** — extra files sit in a `queued` state (dimmed) and start as slots free up; submit stays disabled until none are queued/in-flight. The sidebar is a flex column (`modal.scss` `.modal--sidebar` clips overflow) whose `__body` is the scroll region, so the footer submit stays reachable with many files. **Native file-input drop is used** (no custom drag handlers): the `<input type=file>` fills the dropzone (`opacity: 0`) so dropping onto it just fires `change`. On success a hidden `signed_ids[]` field is added; submit posts them to **`UploadsController#create`**, which turns each signed blob into a `Photo`/`Video` (STI chosen by `blob.video?`) with `uploader: current_user`, then `ui.navigate_to(album_path)` closes the modal and refreshes the timeline. JS-side user-facing strings are passed in from the component as a `labels` Stimulus Object value (server-translated), never hardcoded in the controller.
- **Album menu / sharing.** The hero's **⋯ button** opens an overflow popover (`Components::AlbumMenu`, rendered by `AlbumsController#menu` with `layout: false` — mirrors `PeoplePicker`, lives inside Shimmer's `.popover` chrome): **Share this album**, **Download everything**, and **Everything except mine** (gated on `current_user` — the design's "identified"; the component reads `current_user` itself). Share opens a **QR modal** (`Components::ShareCard` via `AlbumsController#share`): an `rqrcode` SVG of `album_url` injected with `raw(safe(...))`, the link in a copy pill (`clipboard_controller.js` toggles `data-copied` → CSS swaps Copy/Copied), and an info caption. `modal_controller#open` calls `window.ui.popover?.close()` so opening the modal dismisses the menu. **Bulk download** streams a zip via **`zip_kit`** (`AlbumsController#download`, `include ZipKit::RailsStreaming`); `?scope=others` drops the viewer's own uploads (`where.not(uploader_id: current_user.id)`, only when logged in). Menu rows that download are plain `<a data-turbo="false">` so Turbo doesn't intercept the file response. A **Change name** row (top of the menu) is shown only when `policy(@album).update?` (admin only — the component checks the policy directly) and opens the rename modal (`Components::RenameCard` via `AlbumsController#edit`, `authorize @album, :edit?`); its `form_with(model: @album)` PATCHes `AlbumsController#update` (`authorize @album`, `params.expect(album: [:title])`) which `ui.navigate_to(album_path)` to close the modal + morph the grid with the new hero title. Deps: `rqrcode`, `zip_kit`; icons added: `more-horiz`/`share`/`photo-library`/`filter-none`/`content-copy`/`check`/`info`/`edit`.
- **Deleting a moment.** Gated on `MomentPolicy#destroy?` (uploader or admin). The moment detail's action bar shows a trashcan (`Components::MomentDetail#delete_button`) only when `policy(@moment).destroy?` (the component checks it directly). It's a `form_with(method: :delete, data: {turbo_confirm: t(".delete_confirm")})` → **`MomentsController#destroy`** (`authorize @moment`, `@moment.destroy`, `redirect_to album_path`). Icon added: `delete`.
- **Confirm dialogs = Turbo's confirm, restyled.** `data-turbo-confirm` is the universal trigger, but `application.js` calls **`Turbo.setConfirmMethod`** to back it with a **styled `<dialog>`** (`Components::ConfirmDialog`, rendered once in the layout, reuses the design's danger `ModalCard`) instead of the native browser confirm. The method swaps the dialog's message (`.modal-card__subhead p` ← the `data-turbo-confirm` string) and resolves the promise true only when the **Delete** button submits (a native `<form method="dialog">` — one of the few legit raw forms, since `method="dialog"` isn't an HTTP form; buttons report `confirm`/`cancel` via `dialog.returnValue`). So **any future confirm is just `data: {turbo_confirm: "…"}`** on a form/link and gets the design's dialog for free. System specs interact with it as DOM (`within "#confirm-dialog" { click_button "Delete" }`), not Capybara `accept_confirm`.
- **Prev/next navigation.** The moment detail's media stage has circular **prev/next arrow links** (`Components::MomentDetail#nav_arrow`, `chevron-left`/`chevron-right` icons) to the adjacent moment in the **album's chronologic order** — the same `(captured_at, id)` sort the grid uses. `MomentsController#show` computes the neighbours with a **keyset query** (`#neighbour(:before/:after)`, named binds — no SQL-string interpolation) and passes them as `previous_moment`/`next_moment` props; each is **nil at the ends**, so the arrow is simply omitted there (no wraparound). Plain Turbo links (the photo cross-fades on visit). Icons added: `chevron-left`/`chevron-right`.
- **Commenting.** The moment detail's sidebar has a **composer** (`Components::MomentDetail#comment_composer`) between the action bar and the comment list, plus the list itself **newest-first** (`MomentsController#show` orders `created_at: :desc, id: :desc`; empty → a muted "No comments yet" line). Logged in, the composer is a `form_with` (a single-line `input name="comment[body]"` + an `arrow-upward` send button) — **no Stimulus**: a one-input form submits on **Enter** natively, and `required` + a non-whitespace `pattern` let the browser reject an empty/blank comment, so the send button's disabled look is purely cosmetic CSS (`.moment-detail__composer:has(&__composer-field:required:placeholder-shown) &__send` → muted + `pointer-events: none`; the logged-out field has no `required`, so its button stays clickable to open login). Submitting POSTs to **`CommentsController#create`** (`before_action :require_login`), which `create!`s the `Comment` with `author: current_user` (params via `params.expect(comment: [:body])`), and `redirect_to album_moment_path` so Turbo morphs the new comment in. **Logged out**, the composer is a plain `div` (no form/Stimulus) whose send button opens the login modal in the current view (`modal#open` → `new_session_path`, exactly like the heart). **No reply/edit/delete on comments** (the design has edit/delete affordances; out of scope here). Icon added: `arrow-upward`.
- **Passkeys (WebAuthn).** Returning users can sign in with a passkey, and after an email-code login the modal offers to create one. Built on the **`webauthn`** gem (cedarcode) + **`@github/webauthn-json`** npm pkg. **Three layers:** the **`Login::Passkey`** strategy (`app/models/login/passkey.rb`, reached as `login.passkey`) bridges cookies ↔ WebAuthn — `authentication_options`/`verify(credential)`/`registration_options`/`register(credential, nickname:)` stash/read the `:webauthn_challenge` cookie and call `Login#sign_in`, delegating the actual WebAuthn work to the **`Passkey` model class methods** (`authentication_options`/`registration_options`/`verify_authentication`/`register`, grouped under `class << self`, which call `WebAuthn::Credential.from_get`/`from_create` + `.verify` and own the `external_id` lookup, sign-count bump, and `create!`). (Inside `Login::Passkey` the model is referenced as `::Passkey` so the nested class name doesn't shadow it.) The relying party is configured **once at boot** in `config/initializers/webauthn.rb`, inferring origin/rp_id from **`config.action_mailer.default_url_options`** (the same host/port URL helpers + mailer links use — dev `localhost:3000`, prod the real domain) — **no per-request setup, no separate ENV** (set the host once per environment and WebAuthn follows). The `Passkey` class methods call the global `WebAuthn::Credential.options_for_get`/`from_get` etc. (default relying party). The WebAuthn **challenge** is stored in a short-lived encrypted `:webauthn_challenge` cookie (`CHALLENGE_TTL`), the same cookie-jar pattern as `:pending_login`. **`Passkey`** (`belongs_to :user`; `external_id` unique = the credential id, `public_key`, `sign_count`, `nickname`) is the only new table. **Login is discoverable/usernameless** — `Passkey.verify_authentication` finds the `Passkey` by the assertion's credential id and verifies against its stored `public_key`/`sign_count`; **passkey login never find-or-creates a user** (an unknown credential → nil → fails closed; account creation stays email-only). **Everything stays in the Turbo world via a hidden form field, not fetch/JSON:** the controller embeds the server-computed options as a Stimulus Object value (`passkey_options_value`, fed `options.as_json`), `passkey_controller.js` runs `navigator.credentials.*` (`@github/webauthn-json`'s `get`/`create`), drops the JSON result into a hidden `:credential` field, and `requestSubmit()`s a normal `form_with`; the action responds with `ui.navigate_to` (shimmer) just like email verify. **Login reuses `SessionsController#create`** (no new endpoint) — it branches on `params[:credential].present?`. Registration is `POST /passkeys` (`PasskeysController`, `require_login`). The login modal's email field uses **conditional mediation** (`autocomplete="username webauthn"` + `mode: "conditional"`): on connect the controller runs a background `get({mediation:"conditional"})` so passkeys surface as autofill; the email form's `submit->passkey#abort` cancels it if the user types their email instead (degrades silently where unsupported). After email verify, `verify` renders **`Views::Sessions::Passkey`** (the "Add a passkey" offer, icon `passkey`) into the `"login"` frame instead of closing; "Not now" (`passkey#skip`) just `Turbo.visit`s the current page to morph in the signed-in state. Icon added: `passkey`.
- **`Moment` is STI** (`type` column) with `Photo` and `Video` subclasses, one `has_one_attached :file` each.
- **Participants are derived, not a join model.** There is **no `Ownership` table** — `Moment#uploader`, `Comment#author`, and `Like#user` all reference `User` directly. `Album#users` computes the participant list on the fly: the distinct uploaders, **ordered by first upload** (`MIN(moments.created_at)`), memoized + materialized to an array so the per-moment color lookup doesn't re-query. A user's **index in `album.users`** maps to their palette color (no color stored).
- **`captured_at`** (`Moment`, **nullable, no default**) is denormalized for SQL sorting (`scope :chronologic, -> { order(:captured_at, :id) }`) **and doubles as the readiness flag** — it's `nil` until processing finishes, so its presence is what reveals a moment in the grid (see *Readiness & processing pipeline*). On upload, Active Storage's single `AnalyzeJob` runs `CaptureTimeAnalyzer` (prepended, **accepts any image or video** and delegates to the analyzer AS would otherwise use for dimensions/duration), then the `activestorage-after_analyze_attached` gem fires `after_analyze_attached(:file)` — declared on **each STI subclass** (`Photo`/`Video`), since the gem's callback registry isn't inherited and attachments load as the subclass — which runs the shared `Moment#after_file_analyzed`. We never call `analyze` ourselves at request time (avoids a double pass). The analyzer reads **images** (JPEG **and HEIC**) via **libvips** EXIF (`DateTimeOriginal` + `OffsetTimeOriginal` — libvips covers HEIC as well as JPEG, where `exifr` would only handle JPEG) and **videos** via **ffprobe**, preferring `com.apple.quicktime.creationdate` over `creation_time` (the latter is the upload/re-write time on Apple clips). Files with no usable date fall back to the upload time (`created_at`).
- **`User#name`** is auto-filled (when blank) from the email local-part, title-cased: `neo.m@… → "Neo M"`.
- **Readiness & processing pipeline.** A moment is shown in the grid only once it's **ready** — meaning `captured_at` is set, which happens only after its file is analyzed *and* its grid representation/poster is pre-generated, so the grid never triggers representation generation at request time (which is what raced for video posters; see *Gotchas*). There's no separate flag column: `Moment.scope :ready` = `where.not(captured_at: nil)`, `:pending` = `where(captured_at: nil)`. Pipeline: upload `create!`s the moment (`captured_at` nil → pending) → Active Storage's `AnalyzeJob` → the `after_analyze_attached` hook calls the shared `Moment#after_file_analyzed` (declared per STI subclass since the gem's registry isn't inherited), which warms the `[400,nil]`/`[800,nil]` webp the shimmer proxy serves (for video this generates `preview_image` once, single-threaded), then **`update!`s `captured_at` last, in an `ensure`** (already-set value e.g. seeds → file capture time → upload-time fallback) — revealing the moment and firing the broadcast. The `ensure` means a warming failure still reveals the upload (degraded thumbnail) rather than hiding it forever, while the error still propagates (loud). No extra job — the work runs inside the existing `AnalyzeJob`. `AlbumsController#show` loads `.ready` moments and passes `pending_count` (album-wide) to the view, which renders the `Components::ProcessingNotice` pill ("N items still being analyzed") and vanishes it at zero. `MomentsController#show` is also scoped `.ready` (a pending moment 404s rather than render a nil `captured_at`). Jobs are enqueued **after** the surrounding transaction commits (`config.active_job.enqueue_after_transaction_commit = :always` in `config/application.rb`), so a job can never run against records that aren't written yet — the seed still flips to the `:inline` adapter to run jobs *synchronously*, a separate concern from enqueue timing.
- **SQLite write contention.** `config/database.yml`'s `default` anchor sets `default_transaction_mode: immediate` (every env inherits it), so a transaction grabs the write lock at `BEGIN` rather than on first write — cutting `SQLITE_BUSY` errors under concurrent writers.
- **Real-time** (Turbo 8 `broadcasts_refreshes`): `Moment` `broadcasts_refreshes_to :album` (a refresh on create/ready/destroy) and `Like`/`Comment` `broadcasts_refreshes_to ->(r) { r.moment.album }` (because `counter_cache` bumps the count via raw SQL without firing the moment's `after_commit`). So a newly-ready tile pops in (free view transition via the per-tile `view-transition-name`) and like/comment counts stay live for every viewer. Both `Views::Albums::Show` and `Views::Moments::Show` subscribe with `turbo_stream_from(@album)` (the helper is `include`d on `Components::Base` from phlex-rails).

## Domain model

`User` —< `Moment` (`Photo`/`Video`, via `uploader`) —< `Comment` (via `author`), `Like` (via `user`); each `Moment` belongs to an `Album`. An album's participants (`Album#users`) are derived from its moments' uploaders — there is no join model.

## Routing & controllers

Everything is scoped by the album slug (the access key):
- `GET /` (root) → `Albums#index` — the **landing page** (`Views::Albums::Index` → `Components::Landing`). Creating is **admin-only**, so the "Create an album" CTA: logged out → opens the login modal (`new_session_path`, since an admin might be signing in); logged-in **admin** → a `form_with(url: albums_path, method: :post)` submit button; logged-in **non-admin** → no button (the component branches on `current_user` + `policy(Album).create?`). `POST /albums` → `Albums#create` (`before_action :require_login`, then `authorize Album, :create?`) **creates** an empty album and `redirect_to`s it (`redirect_to Album.create!`).
- `GET /albums/:id` → `Albums#show` (`:id` is the slug; `Album#to_param` returns `slug`). Reads `?people=<user_id>,…` to filter.
- `GET /albums/:id/people` → `Albums#people` (**member action**) — renders the `Components::PeoplePicker` popover fragment with `layout: false`.
- `GET /albums/:album_id/moments/:id` → `Moments#show` — the moment is fetched via `@album.moments.find(...)`, so it's only reachable through its own album's slug (a valid id under the wrong slug → 404).
- `GET /files/:id` → shimmer's image proxy.

Controllers find the album with `find_by!(slug:)`, eager-load, and `render Views::…​.new(...)`. `rescue_from ActiveRecord::RecordNotFound` in `ApplicationController` renders **`Views::NotFound`** with `status: :not_found` (the design's "invalid link" screen) — covers both a missing album and a missing moment.

## View layer (Phlex)

Set up in `config/initializers/phlex.rb`: two autoload namespaces — **`Components::`** (`app/components`, reusable building blocks) and **`Views::`** (`app/views`, one per controller action, e.g. `Views::Albums::Show`). `Components` is a `Phlex::Kit`. `Components::Base < Phlex::HTML` `extend`s `Literal::Properties` and includes the Phlex::Rails helpers (Routes, ImageTag, Translate, L, Pluralize); `Views::Base < Components::Base`.

- **Props via `prop` (literal gem):** `prop :name, Type`, read as `@name`. **Make props type-safe** — constrain enums with `_Union(*KEYS)` (e.g. `Text#color`, `Icon#name`) so an invalid value raises at construction. **Type collection elements** with `_Enumerable(Type)` (e.g. `_Enumerable(User)`, `_Enumerable(::Comment)` — use `::` for a model that a `Components::` class would shadow), never a bare `Enumerable`, so the element type is visible.
- **Rendering:** primitives have lowercase shorthands defined on `Base` — `text(...)`, `stack(...)`, `icon(...)` — use those, not `render Components::Text.new`. Domain components use `render Components::X.new(...)`. The controller renders the page **view** directly (`render Views::Albums::Show.new(...)`); phlex-rails wraps it in the app layout. **All loading/eager-loading happens in the controller**, not in the view or model methods.
- **Always build forms with `form_with`** (`include Phlex::Rails::Helpers::FormWith`), never a raw `form` element. It injects the CSRF token and the `_method` override for you — so never hand-write `<input name="authenticity_token">` or `_method` hidden fields (and don't reach for `FormAuthenticityToken`). Pass `method:`/`url:`/`data:` as options (e.g. `form_with(url: verify_session_path, method: :patch, data: {turbo_frame: "login"})`). Yield the builder — **always name the block argument `f`** (`do |f|`) — and use the **Rails field helpers** for inputs/buttons — `f.email_field`, `f.text_field`, `f.button`, etc. — not raw `input`/`button` elements. The phlex-rails builder renders each helper straight into the Phlex buffer.
- **`ApplicationFormBuilder`** (`app/form_builders/`, set as `config.action_view.default_form_builder`) is the app-wide default, and its field/button methods **render Phlex components**: `f.text_field`/`f.email_field`/`f.code_field` → `Components::Field`, `f.button` → `Components::Button` — no per-call wiring (each field method also sets that type's sensible `inputmode`/`autocomplete` defaults). `Field`'s `type` (`:text`/`:email`/`:code`) is a single `_Union` — a code field is its own type (a styled text input), *not* a text field plus a variant. `Field` (own `field.scss`) is a pure presentational input — it takes concrete `name:`/`id:` (plus `type:`/`options:`), not a form builder; the builder translates the bound object/attribute into those via `field_name`/`field_id` and renders the component. **Standalone buttons/links that aren't a form submit** — a modal-dismiss, a nav link — render `Components::Button` directly (`variant: :primary | :ghost`, `href:` makes it an `<a>`, `data:` carries Stimulus bindings). Both paths share the one `Button`/`button.scss`.
- **Colocated CSS:** every component ships a sibling `.scss` of the same basename (`hero.rb` + `hero.scss`), **no leading underscore**; the Vite entrypoint glob-imports `app/components/**/*.scss`. **Class name matches the component name** (root `.hero`, BEM children `.hero__people`; `DaySection` → `.day-section__header`/`.day-section__grid`). Components are **self-contained** — never style another component's classes from a different file. **This includes `Text`** (and every other primitive): a component must never write `.text--title3 { margin… }` or otherwise reach into a child component to position or space it. To put space *between* components use a **`Stack`** (gap); to add **padding** (per side, per breakpoint) wrap them in a **`Box`**. Only ever reach for margin/padding on a component's *own* BEM elements (e.g. `.moment-detail__actions`), never on a class it doesn't own. **Views carry no CSS** (they only orchestrate components); base element styles live in `app/frontend/styles/reset.css`.
- **Design tokens** (`app/frontend/styles/tokens.scss`) are `:root` CSS custom properties; **colors are prefixed `--color-`** with semantic names (`--color-background`, `--color-text`, `--color-text-secondary`, `--color-text-muted`, `--color-text-inverse`, `--color-accent`, `--color-surface`, `--color-surface-sunk`, `--color-media-backdrop`, `--color-chrome`, `--color-hairline`). Fonts (`--font-brand`/`--font-ui`) are defined in the **Text** component, not tokens.
- **i18n is component-relative:** `t(".key")` resolves to the component's path (`Components::Hero` → `components.hero.summary`); nest locale keys under `components.<name>`. Dates via `l(date, format: :album_day)` (format in `config/locales`). Never hardcode user-facing strings; never `strftime`.
- **Primitives:**
  - **`Text`** owns all typography **and the fonts**; variants `h1`/`body`/`caption-bold`/`caption`/`label`. `.text` sets no base color (it inherits; variants and the `color` prop override). `color` takes a semantic name (`default`/`secondary`/`muted`) mapped to a `--color-*` token.
  - **`Stack`** is the canonical shimmer component (class `.shimmer-components-stack`, copied verbatim from `nerdgeschoss/shimmer-components`): `gap` is an inline `--gap` custom property, with responsive `*_tablet/_desktop/_widescreen` props (breakpoints 640/890/1280).
  - **`Box`** is the padding primitive (class `.box`): per-side props `top`/`right`/`bottom`/`left` with responsive `*_tablet/_desktop/_widescreen` variants, emitted as `--box-p{t,r,b,l}*` custom properties that cascade up the breakpoints like Stack's gap. Use it instead of margins/padding that would otherwise leak across component boundaries. Both `Stack` and `Box` have lowercase shorthands on `Base` (`stack(...)`, `box(...)`).
  - **`Icon`** renders a `<span>` masked by an SVG file in `app/components/icons/` (`mask-image: url("./icons/<name>.svg")`, tinted via `background-color: currentColor`). Add an icon = drop an SVG in that folder + a `.icon--<name>` rule + extend `Icon::NAMES`.
- **Views are User-centric; per-album color comes from user order.** A user's color is its **index in `album.users`** (ordered by first upload — no `color` on `User`; `album.users` *is* the ordered list). Views get the `User` via `comment.author` / `moment.uploader` directly. **`Moment#uploader_color` and `Comment#author_color` are derived methods** that find the user's index in `album.users` and return the **actual color** — `Components::Palette.new.hex(index)` (a comment-only author who never uploaded falls just past the list into the next slot). `Components::Palette` is stateless and index-based (`hex(index)`; index 0 = ember). **`Avatar` takes a `user` and a `color` (hex string)**; in Hero/PeoplePicker the index comes from `each_with_index` (`Palette.new.hex(index)`). The moment tile's fallback gradient is derived from `uploader_color` in the component. Filtering is by **user id** (`?people=<user_id>,…`, `selected_user_ids`, intersected with the album's participants in the controller).
- **Images via shimmer:** `image_tag(attachment, width: 400)` uses shimmer's `image_tag` override (webp proxy, lazy, 2× srcset) — activated by `include Shimmer::FileHelper` in `ApplicationController`, served via the `file` route (`get "files/:id" => "shimmer/files#show"`). The proxy uses `resize_to_limit`; square tiles crop via CSS `object-fit: cover`. The poster URL alone comes from `image_file_path` (registered as a Phlex value helper on `Base`). **`Video` moments in the detail render a real `<video controls>`** (`<source>` = `rails_blob_path(file)`, `poster:` = the shimmer webp proxy); photos render `image_tag`. Video posters/duration need ffmpeg.

## Testing

- **Minitest specs with RSpec matchers.** Files are `class XxxTest < ActiveSupport::TestCase` using `describe`/`it` (Minitest spec DSL, enabled in `test/test_helper.rb`) and `expect(...).to ...` (`rspec/expectations/minitest_integration`). Group examples with nested `describe` (the equivalent of RSpec `context`). **Always use RSpec matchers, never Minitest `assert_*`/`refute_*`** — e.g. `expect { … }.to change { … }`, `expect(page).to have_css(…)`/`have_no_css(…)` (Capybara's RSpec matchers in system specs), not `assert_difference`/`assert_selector`.
- **Fixtures come from Oaken seeds**, not YAML. `db/seeds/albums.rb` builds one labelled "Lisbon & the Algarve" dataset shared by `bin/rails db:seed` and the test suite (`include Oaken.loader.test_setup`). The album has a fixed `slug: "test"`. Photos (`db/seeds/files/photos/`) are cycled across moments; **video moments attach a real clip** (`db/seeds/files/videos/movie-short.mp4`). Each moment is created **ready**: the seed runs jobs **inline** (the test queue adapter doesn't run jobs, and inline keeps Active Storage's auto-enqueued `AnalyzeJob` off a running dev worker that would race the warming), so attaching each file analyzes it, warms the grid representation, and sets `captured_at` via the `after_file_analyzed` hook. The seed passes a curated `captured_at:` per moment, which wins over the file's own date (the hook's precedence), so the whole dataset stays on the intended June-2026 timeline (videos included; they still pick up `duration` from analysis). Needs libvips + ffmpeg (hard deps). The first two days are tripled → **33 moments** total. Reference records as `albums.lisbon`, `users.priya`, `users.marco` (the site admin), `photos.tram`, `users.nomad` (a user with no uploads), etc.
- **Don't test Rails-guaranteed behavior** (counter caches, STI dispatch, `dependent: :destroy`, associations, standard validators). Test our own logic only.
- **No controller/request specs.** Tests are: **model specs** (`test/models/`) for our model logic — which is *why* logic lives in models, not controllers — **policy specs** (`test/policies/`) for pure-Ruby authorization logic (instantiate the policy directly: `AlbumPolicy.new(user, record).create?`), and **system specs** (`test/system/`) that drive a whole feature end-to-end. If you reach for a controller test, push the logic into a model/policy and unit-test it there, or cover the behavior with a system spec. **Keep system specs lean** — cover the *main flows* the typical user runs (don't add a system test per permission branch; that belongs in a policy spec).
- **System tests** (`test/system/`, Minitest) drive a real Chromium via **Playwright** (`capybara-playwright-driver`). The driver is registered as `:vesker_playwright` in `test/application_system_test_case.rb` — **don't name it `:playwright`** (the gem reserves that). The browser is installed once with `npx playwright install chromium`. They are **not** in the default `bin/rails test`; run `bin/rails test:system` (prefer `PARALLEL_WORKERS=1`). Keep them behavioral — no screenshots in committed tests.
- **Lint test** (`test/lint_test.rb`) runs `bin/rubocop` and `bin/brakeman` via `Open3.capture2e` and asserts a clean exit — silent on success, surfacing the tool output only on failure. It uses `assert …, output` (not `expect`) so the failure message carries the offenses. There's one EXIF fixture with a real capture time: `test/fixtures/files/exif_sample.jpg`.
- **Email assertions** go through `MailHelper` (`test/support/mail_helper.rb`, included into every test): `run_jobs` drains the ActiveJob queue (mail is `deliver_later`), then `last_mail`/`last_mail!` return a `TestMail` wrapper (`.to`/`.from`/`.subject`, `.text`, `.link_urls`). `deliveries` are cleared before each test. Don't reach into `ActionMailer::Base.deliveries` directly.

- **RuboCop = Shimmer's StandardRB-based config** (`inherit_gem: { shimmer: config/rubocop_base.yml }`, via the `standard` + `rubocop-rails` gems). Run `bin/rubocop`.

## Frontend

JS/assets are bundled with **Vite** (`vite_rails`): entrypoint `app/frontend/entrypoints/application.js` (imports Turbo/Stimulus/shimmer + `reset.css`/`tokens.scss`/`popover.scss`, then glob-imports `app/components/**/*.scss`), config in `config/vite.json` + `vite.config.ts`, loaded in the layout via `vite_client_tag` + `vite_javascript_tag "application"`. SCSS via the `sass` npm dep. JS deps are managed with **npm** (node 24 / npm 11; not Bun).

- **Never run `bin/vite build`.** The dev server (`bin/vite dev`) serves assets automatically (the Rails proxy is on — no `skipProxy` in `config/vite.json`), and tests use the test-env auto-build. Running `bin/vite build` writes stale compiled output into `public/vite*` that later masks your real changes and causes confusing debugging. To verify CSS/JS, use the dev server or run a system test.
- **Don't hand-write vendor prefixes** (`-webkit-`, etc.). `autoprefixer` (`postcss.config.js` + the `browserslist` in `package.json`) adds them automatically.
- **JS wiring** (in `application.js`): Turbo, `@nerdgeschoss/shimmer` (call `start({ application })`), and a Stimulus `Application` are started; custom controllers live in `app/frontend/controllers/` and are `register`ed there.
- **Popovers/menus use Shimmer's popover** (`window.ui.popover.open({ url, selector, placement })`) — it lazy-loads its body from `url` (server renders a Phlex component with `layout: false`, e.g. `Albums#people` → `Components::PeoplePicker`). **Phlex blocks `javascript:` hrefs and `onclick`** (XSS guard), so shimmer's `popover_path` helper can't be used from Phlex — trigger via a small Stimulus controller (`popover_controller.js`) instead. That controller **must `event.stopPropagation()`**, or shimmer's own click-outside handler catches the same click and closes the popover instantly. A `turbo:before-visit` listener (in `application.js`) closes any open popover before navigation, so its lingering click-outside listener doesn't swallow the first click on the next page. Style the shimmer chrome (`.popover`, `.popover__content`, `.popover__arrow`) in `app/frontend/styles/popover.scss`.
- **URL-driven filtering + view transitions:** controls are plain links that change query params (e.g. `?people=id1,id2`); the controller re-renders and Turbo's view transition animates the elements. The whole moment tile (and the detail photo) carry `view-transition-name: moment-<id>` (inline, so the color bar/overlays move *with* the photo); day headers carry `view-transition-name: day-<iso>`; the moment-detail sidebar has its own name + `::view-transition-old/new` keyframes (slides in/out while the backdrop cross-fades via root).
- **CSS minifier must be esbuild** (`build.cssMinify: 'esbuild'` in `vite.config.ts`, `esbuild` is a dev dep): Vite 8 here is rolldown-based and defaults to **lightningcss**, which *drops* `view-transition-name` / `::view-transition-*` for the broad `browserslist`. `view-transition-name`s set inline in HTML survive regardless, but the `::view-transition-*` animation rules live in SCSS and only survive under esbuild.

## Gotchas

- **Video posters / duration / capture-time for non-JPEG** need the `ffmpeg` CLI at runtime. The dev-container base image doesn't ship it, so **`bin/setup` installs it** (`apt-get install ffmpeg`) — it's there after a container rebuild, but **not guaranteed in CI**. `libvips` is present as a library (image variants/dimensions work) but the `vips` CLI isn't. Without ffmpeg the video seed still loads, but `Video#duration` and the poster frame come back empty.
- **Custom AS analyzer registration:** amend `config.active_storage.analyzers` inside `config.after_initialize` (`config/initializers/active_storage_analyzers.rb`) — the railtie copies config → `ActiveStorage.analyzers` in *its* after_initialize, so mutating the live array there gets overwritten.
- After changing a not-yet-committed migration, roll back the later domain migrations (`bin/rails db:rollback STEP=n`), edit, then `db:migrate` — the domain migrations are uncommitted.
- **Video poster race — structurally prevented by readiness gating.** Generating a video poster lazily on a `/files/<id>` GET is unsafe under concurrency: shimmer `FileProxy` calls `blob.representation(...).processed`; for a previewable (video) blob that runs `ActiveStorage::Preview#processed` → `variant.processed if variant?`, where `variant` is `blob.preview_image.variant(...)`. `Attached::One` is `delegate_missing_to :attachment, allow_nil: true`, so when two requests both run `process` (racing the `has_one` poster extraction) one sees `preview_image` momentarily unattached → `variant` returns **nil** → `nil.processed` → 500. Photos never hit it (`Variant#processed` never returns nil). **The fix:** moments are only shown once `captured_at` is set, and `Moment#after_file_analyzed` warms the poster/representation (inside Active Storage's `AnalyzeJob`) *before* setting `captured_at` — so the grid never links a tile whose representation isn't already materialized, and no request-time generation (or race) can occur (see *Readiness & processing pipeline*). The detail page is `.ready`-scoped too, so a not-yet-ready moment 404s instead of racing a single (already-safe) generation.
- **minitest 6 has no `minitest/mock`** (it was removed; `Object#stub` is gone). To stub a method in a model spec, swap the singleton method and restore it in `ensure` (see `test/models/passkey_test.rb`'s `stub_credential`). Don't `require "minitest/mock"` — it `LoadError`s.
- **WebAuthn system tests need a `localhost` host + a virtual authenticator.** The relying party is configured from `default_url_options` (`example.com` in test), but the Capybara server runs on a dynamic `localhost` port and the browser rejects a passkey whose rp_id is a raw IP — so the test must point both Capybara *and* the global config at the real origin: `Capybara.app_host = "http://localhost:#{Capybara.current_session.server.port}"`, `WebAuthn.configuration.allowed_origins = [origin]`, `WebAuthn.configuration.rp_id = "localhost"` (restore all three in `ensure`). Register a CTAP2 authenticator over CDP (`page.driver.with_playwright_page { |pw| cdp = pw.context.new_cdp_session(pw); cdp.send_message("WebAuthn.enable"); cdp.send_message("WebAuthn.addVirtualAuthenticator", params: {options: {protocol:"ctap2", transport:"internal", hasResidentKey:true, hasUserVerification:true, isUserVerified:true}}) }`) — see `test/system/passkey_test.rb`. Don't assert the passkey-create inside `expect { … }.to change(Passkey,:count)` — the async create+submit+navigate commits *after* the change-matcher snapshots; assert `User…passkeys.count` *after* `have_no_css(".modal--open")` instead.
